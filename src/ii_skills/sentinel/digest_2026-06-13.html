Claude Fable 5 launches June 9 — Mythos-class model made public, 1M context, free until June 22 FREE NOW
Anthropic shipped Claude Fable 5 on June 9 — the first publicly available version of its Mythos frontier model. 02  CLAUDE CODE
Nested sub-agents go 5 levels deep — Claude Code breaks its own 2-year rule
Shipped in v2.1.172 (June 10), sub-agents can now spawn their own sub-agents up to 5 levels deep. For two years, the docs stated in three places that a sub-agent could not spawn another sub-agent — Boris Cherny reversed that on June 9 with a quiet note that the 5-level cap is a "starting point" and he's collecting feedback. The motivation: "agents kicking off agents as a way to better manage context." Architecturally, this is the missing primitive for recursive decomposition: a lead agent can dispatch an investigation, each investigator can spawn data collectors, each collector can call formatting sub-agents — all within one Claude Code session and no external orchestration code. For ii-agent, this directly enables a dispatcher → toolkit-module → Excel-writer → PPT-mirror chain.
03  CLAUDE CODE
8 releases in 7 days — post-session hooks, fallback models, /cd, and safe-mode ship
Claude Code shipped versions 2.1.160 through 2.1.176 this week. The four most operationally useful additions for ii-agent: (1) post-session lifecycle hook (v2.1.169) — runs after a session ends before workspace deletion, enabling automatic archiving of Tier 3 case outputs; (2) fallbackModel setting (v2.1.166) — up to three ordered fallback models tried when the primary is unavailable, essential for scheduled newsletter runs; (3) /cd command (v2.1.169) — moves a session to a new working directory without breaking prompt cache; (4) Marketplace plugin search bar (v2.1.172) — searchable /plugin browser. Also added: disableBundledSkills setting to suppress built-in skills when custom ones should take precedence, and MAX_THINKING_TOKENS=0 to disable extended thinking on supporting models.
04  OPENAI
OpenAI sunsets Agent Builder and Evals — November 30 deadline, migrate to Agents SDK
On June 3, OpenAI announced it is winding down Agent Builder and the Evals product; both go offline November 30, 2026. The official guidance is to migrate to the OpenAI Agents SDK (released March 2026), which wraps the Responses API — the production interface that has processed trillions of tokens since March 2025 — with handoffs, guardrails, and tracing. This accelerates the consolidation happening across the agent stack: OpenAI Agents SDK, Google ADK (now in Java 1.0 and Go 1.0), and the Claude Agent SDK are the three production-grade framework targets. Microsoft has simultaneously merged AutoGen and Semantic Kernel into a single Microsoft Agent Framework 1.0. The no-code/low-code agent builder era is ending; the SDK era is the next phase.
05  MCP
MCP 2026-07-28 Release Candidate locks stateless protocol — July 28 final spec, 10-week window
The largest revision of MCP since launch is locked as a release candidate. The core change: the initialize handshake and Mcp-Session-Id header are eliminated — every request is now fully self-contained, enabling remote MCP servers to run behind plain round-robin load balancers with zero sticky sessions or shared stores. State that used to live in the session (browser handles, basket IDs) is now passed as explicit arguments — visible, auditable, and composable. New routable headers (Mcp-Method, Mcp-Name) let gateways route without body inspection. The Extensions framework adds Tasks (long-running work via handles) and MCP Apps (server-rendered HTML UIs). OAuth aligns with RFC 9207. Final spec ships July 28. If any ii-agent skill ever exposes an MCP server, this is the architecture to target. Migration window: 10 weeks from May 21.
Architecture Watch
5-level nested sub-agents reframe ii-agent's skill dispatch model design change
The current ii-agent pattern is flat: Claude Code dispatches a single skill, that skill runs sequentially, outputs land in Tier 3. With 5-level nesting, the pattern becomes recursive: a case orchestrator dispatches a module coordinator that dispatches parallel module agents (Sources & Uses, Revenue Build, Debt Schedule, Returns) that each dispatch a formula validator. This mirrors the Dynamic Workflows ultracode pattern but is now achievable in standard Claude Code sessions without the workflow toggle. The new design question is not "which skill to call" but "what depth of delegation is appropriate for this request."
Context Engineering is 2026's primary discipline — Anthropic formalizes the framework
Anthropic published "Effective Context Engineering for AI Agents" this week, formalizing the shift from prompt engineering (how you write instructions) to context engineering (what information is in the context window, and when). Three primitives: attention budget (not everything fits — prioritize signal over noise), just-in-time retrieval (fetch context at decision points, not at session start), and sub-agent patterns (use sub-agents to parallelize context loading). For ii-agent, this validates the deal_memory injection pattern: don't dump all deal memory at session start — pull the relevant deal slice when a specific module is dispatched.
The 1M context window changes what "single-session" means for deal work ii-agent relevant
With Fable 5's 1M token window (free through June 22), a full CIM PDF (~200 pages, ~150k tokens), a precedent transaction set, a sector playbook, and an in-progress LBO model can co-exist in one context with 600k+ tokens to spare. This eliminates the chunk-and-retrieve pattern for CIM analysis — no need for pdf_extractor's segment-by-segment approach on a standard-sized CIM. Simon Willison tested this and reported Fable 5 "spotted and fixed bugs in a dependency injection utility library I had in context" without being asked — the model acts on the full context proactively.
MCP going stateless — the "handle as argument" pattern is the new normal
The 2026-07-28 RC enforces a clean architectural principle: any resource that used to be implicit in a session (a browser, a spreadsheet, a search context) is now an explicit handle passed as a function argument. This makes multi-step tool chains fully auditable — every state transition is visible in the tool call log. For ii-agent skill design, this is already the right pattern (each Excel workbook is a file path argument, not a shared session object) — the MCP spec is now catching up to that convention.

fallbackModel setting — resilience for automated newsletter runs wire this up
Added in v2.1.166, the fallbackModel setting accepts an ordered list of up to three model IDs. When the primary model is unavailable (rate limited, quota exhausted, or temporarily offline), Claude Code tries the next model in the list automatically. For ii-agent's networth, market, and health runners: set primary = Opus 4.8, fallback[0] = Haiku 4.5. The newsletters run correctly at lower cost when the primary quota is hit, instead of failing silently.
post-session lifecycle hook — auto-archive Tier 3 case outputs build this
Added in v2.1.169 for self-hosted runners, post-session runs a shell command after a session ends before the workspace is deleted. Wire this to a script that copies the output/cases/ directory to a stable location, logs the session metadata, and optionally emails a delivery confirmation. This is the missing automation link between Claude Code's ephemeral workspace and ii-agent's persistent Tier 3 folder structure.
Mem0 (52k stars) — persistent memory layer for agent continuity
Mem0 is one of the fastest-growing repos in the AI agent space (52k stars). It provides a persistent, queryable memory store for agents — semantic search over stored facts, entity-level memory (people, companies, deals), and automatic memory extraction from conversations. The ii-agent deal_memory skill solves the same problem with a custom DataStore. Worth evaluating Mem0 as a drop-in alternative: it has native MCP server support and a managed cloud tier, which could replace the bespoke memory.py/datastore.py stack with a well-maintained OSS dependency.
