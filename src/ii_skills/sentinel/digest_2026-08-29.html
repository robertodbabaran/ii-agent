Top 5 Headlines
01  ·  Anthropic
Claude Code Auto Mode Is Now the Default (Aug 14)

Anthropic flipped auto mode on for all Pro, Max, and Team plans. In a 1,053-action study, auto mode blocked 89% of harmful actions versus just 13.6% when humans clicked through prompts — and users had been approving 97% of those prompts anyway. The change does not affect running sessions and remains opt-out. Enterprise and API access follow next month.

02  ·  MCP
MCP 2026-07-28 Spec Finalized + New Roadmap Published (Aug 22)

The MCP 2026-07-28 specification is now final. The headline change: MCP goes stateless — the protocol-level session handshake is gone, making remote servers ordinary HTTP services that scale horizontally without managing state. New extensions ship Apps (server-rendered UIs) and Tasks (long-running work). The Aug 22 roadmap adds five new priorities: agentic messaging primitives (webhooks, channels), HTTP-native transport unification for local servers, agent identity via Workload Identity Federation, progressive tool discovery, and better SDK DX across language platforms.

03  ·  Research
Lilian Weng: "Harness Engineering for Self-Improvement"

Published July 4, this post reframes how to think about agent systems. Beyond "agent = LLM + memory + tools + planning," harness engineering adds workflow design (loop architecture), evaluation, permission controls, and persistent state management as first-class system concerns. It positions the runtime and surrounding software infrastructure — not just the prompt — as the core design surface.

04  ·  AWS
Amazon Bedrock AgentCore Runtime Instances Go GA

Agents can now run on any EC2 instance type without managing infrastructure — AgentCore handles provisioning, patching, scaling, and lifecycle. This matters for sustained, resource-intensive, or specialized-hardware workloads. Also shipped this week: cross-account agent registry sharing via AWS RAM with four managed permission levels (ReadOnly, Consumer, Publisher, Admin).

05  ·  Anthropic
Mid-Conversation Tool Changes Now in Beta on Claude Fable 5 / Opus 5

The Claude Developer Platform now supports changing the active tool set mid-conversation without starting a new session. Available in beta on Claude Fable 5, Mythos 5, Opus 4.8, and Opus 5. This enables adaptive agent workflows where tool availability changes based on context or user permissions.

Architecture Watch
MCP Goes Stateless
HTTP-native scaling changes the deployment model

A remote MCP server is now just an HTTP service — no session state, no sticky routing, trivially scalable behind a load balancer. ii-agent's MCP integrations can move from local stdio processes to deployed HTTP endpoints without any protocol rework.

Harness Engineering
The runtime layer is the new design surface

Weng's framing separates the agent harness (loop design, eval, permissions, state) from the agent itself. In ii-agent terms: the scheduled task runner, budget controls, and skill dispatch are the harness — and they deserve the same design rigor as the prompts and tools.

Multi-Agent Reality Check
40% of multi-agent pilots fail within 6 months

Production data shows multi-agent adds 2.1 percentage points of accuracy at roughly double the cost. Pipeline (linear handoff) is the most reliable pattern. Fan-out, debate, and swarm patterns have much higher failure rates when poorly matched to the problem. Simpler beats clever.

Capability Spotlight
MCP Extensions
Apps extension — server-rendered UIs in MCP

MCP servers can now push embedded UI components directly into the client. This means tools can render interactive forms, charts, or controls in the Claude Code UI without the agent writing separate HTML artifacts.

Claude Code
Cross-session messaging + restricted mode

Claude Code now supports cross-session messaging (agents sending messages to other agents across sessions) and a restricted mode that locks down file system and shell access. Critical for ii-agent scheduled tasks — restricted mode can sandbox automation runs cleanly.

GitHub Trending
browser-use: headless browser access for LLM agents

Built on Playwright + LangChain/LlamaIndex, browser-use gives agents the ability to navigate real web applications, click buttons, and fill dynamic forms. Relevant for ii-agent's market research and news aggregation workflows that currently hit paywalls or require JS rendering.

Claude SDK (Beta)
Managed agent controls: session budgets + advisor models

The Claude Developer Platform now exposes session-level token budgets, advisor model configuration, and inference geo pinning at the managed agent level. GitHub-hosted skills are also now available. Budget controls are immediately useful for ii-agent's scheduled runs to prevent runaway token spend.

Workflow Ideas
Prompt Pattern
Lean into auto mode for all scheduled tasks

Now that auto mode is the default and demonstrably safer than click-through prompts, ii-agent's scheduled newsletters and Sentinel runs should explicitly set auto mode. Remove any residual approval gates in routine automation — they were adding friction without safety.

Architecture
Add an evaluation loop to each skill run

Inspired by Weng's harness engineering: each skill (networth, market, health) could include a self-evaluation step — "did this output meet the quality bar?" — before emailing. A simple rubric check by a fast model (Haiku 4.5) adds a validation gate without much cost.

Tooling
Evaluate browser-use for research workflows

The daily investment newsletter and market newsletter currently rely on NewsAPI and static fetches. browser-use could enable dynamic page scraping for sources that require JS or login. Worth a proof-of-concept for one newsletter before broader adoption.
